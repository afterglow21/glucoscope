# GlucoScope Plus 返金・問い合わせ運用手順

Status: operator runbook accepted / public contact and live payment-refund receipt accepted / retention review remains an operating duty

Last reviewed: 2026-08-17 JST

## 1. 目的と停止条件

この手順は、少人数向けのGlucoScope Plus 30日パスについて、問い合わせを安全に受け、二重決済やPlus未付与をまず訂正し、必要な場合だけStripeで全額返金し、対応するPlusを終了して結果を返信するための運営者用手順である。

販売開始の承認ではない。Stripe test modeでこの手順を最初から最後まで実行し、Webhook、Plus終了、失敗時の説明、異議申立て境界を確認するまでは、購入・Checkout・Webhook・販売準備の全switchを停止したままにする。

## 2. 公開窓口と返信目安

- 公開窓口：`support@glucoscope.app`
- 受付：平日
- 最初の返信：原則5営業日以内
- 緊急対応、診断、治療、インスリン量、医療機器設定の相談窓口ではない
- Cloudflare Email Routingによる非公開受信箱への転送と、別送信元からの実受信は2026年8月17日に確認済み

## 3. 利用者へ送ってよい案内

問い合わせには、次の最小情報だけを依頼する。

1. 購入に使ったメールアドレスから送ること
2. おおよその購入日
3. 「二重決済」「Plusが始まらない」「大きな障害」「販売者情報の開示請求」「その他」のどれか
4. 困っている操作と、画面に表示された一般的なエラー文

次の情報は送らないよう明記する。

- カード番号、セキュリティコード、Stripeやメールのパスワード
- Nightscout・GlurooのURL、合言葉、API Secret
- 血糖値の一覧、グラフ、インスリン量、治療内容、医療機器設定
- 子どもの氏名、生年月日、学校名など、購入確認に不要な個人情報

購入メール以外から届いた場合、カード情報や本人確認書類を求めない。Plusの通常のメールコード認証・復旧導線を案内するか、購入メールから送り直してもらう。

## 4. 一次受付

1. 受信日時と、依頼の種類だけを確認する。
2. 通常の問い合わせは平日5営業日以内を目安に、受領したことと次の確認内容を返信する。
3. メール本文に健康情報や秘密情報が含まれていた場合、返信で再掲しない。今後送らないようやさしく案内する。
4. 返金を約束する前に、購入と現在状態を確認する。

### 販売者情報の開示請求

- 「販売者情報の開示請求」は通常の購入照合や返金受付と分け、購入の申込み前に十分確認できるよう優先して遅滞なく対応する。
- 購入メール、購入日、本人確認書類、カード情報は求めない。返信先として使われたメールアドレスだけで受け付ける。
- 販売者本人が管理する非公開の正本から、戸籍上の氏名または登記商号、現に活動する正確な住所、確実に連絡できる電話番号を転記する。Git、公開ページ、運用ログ、別の台帳へ値を保存しない。
- 返信前に3項目を販売者本人が再確認し、申込みより前に届いたことを相手が確認できる余裕を確保する。返信できない間は販売を開始しない。
5. メール件名へStripe ID、アカウントID、カード情報を追記しない。

## 5. 購入の照合

Stripe DashboardはMFAを有効にした運営者アカウントで開く。API keyをチャット、メール、Git、メモへコピーしない。

1. StripeのPaymentsで、購入メール、おおよその購入日、JPY 400を使って候補を探す。
2. GlucoScope Plus 30日パスの正しいProduct・Price・Checkoutであることを確認する。
3. 支払いが成功済みであること、返金済みでないこと、同じ購入に未解決の異議申立てがないことを確認する。
4. Plus側では、確認済みアカウント、Checkout、支払い、利用権の対応が一致することを、安全な照会画面または将来の運営ツールで確認する。D1を直接編集して帳尻を合わせない。
5. 一致を安全に確認できない場合は返金操作へ進まず、販売を停止したまま照会手段を直す。

## 6. 判断

### まず訂正する

- 二重決済：1回の購入に対する重複であることを確認し、正しい1件を残す。
- 支払い済み・Plus未付与：Webhook再処理や安全な復旧で利用権を正しく開始できるか確認する。
- 再購入を解決手段にしない。

### 全額返金する

- 二重決済を安全に訂正できない場合
- 支払い済みなのにPlusを開始できず、運営側でも解決できない場合
- GlucoScope側の大きな障害で主なPlus特典をほとんど利用できず、運営側でも解決できない場合

部分返金は行わない。利用者都合を含むすべての相談が自動的な返金対象になるとは案内しない。対象外と判断する場合も、確認した事実と理由を短く、責めない言葉で返信する。

## 7. Stripe Dashboardでの全額返金

1. 対象のPaymentを開き、金額、通貨、購入者、状態をもう一度確認する。
2. 異議申立てがopenの場合は、通常の返金を同時に行わずStripeのdispute手順で処理する。
3. 「Refund payment」を選び、必ず全額を選ぶ。
4. 理由は事実に合わせる。重複ならduplicate、それ以外の承認済み返金ならrequested by customer相当を選び、必要な場合だけ健康情報を含まない短い内部メモを残す。
5. 最終確認でJPY 400の全額、正しいPayment、重複操作でないことを確認して実行する。
6. Dashboardでrefundの状態を確認する。`pending`や`failed`を`成功`と案内しない。

## 8. WebhookとPlus終了の確認

1. Stripe署名を検証したWebhookだけを受け入れる。
2. `refund.created`、`refund.updated`、`charge.refunded`の再取得・照合後、成功した返金だけが対応する利用権を`refunded`へ変えることを確認する。
3. 同じeventが複数回届いても、返金記録とPlus終了が重複しないことを確認する。
4. ブラウザを再読込し、返金した支払いのPlus特典が使えないことを確認する。
5. Webhookが届かない、照合できない、Plusが終了しない場合は販売を停止し、D1を直接書き換えず原因を直す。

## 9. 利用者への返信

### 受領時

> お問い合わせを受け取りました。購入とPlusの状態を確認します。原則5営業日以内を目安にご連絡します。カード番号、パスワード、血糖値や接続情報は送らないでください。

### 返金開始時

> 状況を確認し、JPY 400の全額返金をStripeで開始しました。対応するPlusは終了します。支払元への反映には、カード会社や銀行により通常5〜10営業日ほどかかる場合があります。反映日をGlucoScopeが保証するものではありません。

### 返金がpendingまたはfailedの時

> 返金処理はまだ完了していません。現在の状態をStripeで確認し、進展があり次第ご連絡します。完了前に返金済みとはご案内しません。

## 10. 記録と削除

- サポート受信箱には、必要な連絡と解決確認だけを残す。健康情報や秘密情報を別の台帳へ転載しない。
- 会計用記録は、商品、金額、通貨、支払い・返金状態と日時、Plus対象期間、Stripe照合番号へ限定する。
- 表示名、血糖値、CGM接続情報、AIお手紙、カード番号、完全なメールアドレスを会計記録へ保存しない。
- 解決済みの通常問い合わせは解決後180日を目安に削除する。未解決の返金・異議申立て・法令上の保全が必要なものは、その理由が続く間だけ保持し、解決後に削除時期を見直す。
- 利用者がPlusアカウントを削除すると、処理中の支払い・返金がない限り、メール照合情報、本人・保護者確認、sessionを直ちに切り離す。確定済み購入の最小会計記録は残り、削除だけで返金にはならない。
- 会計記録は、商品、金額、通貨、支払い・返金状態と日時、Plus対象期間、Stripe照合番号だけに限定し、取引または最終返金から7年保持する。毎年、事業形態と適用ルールに変更がないか確認する。

## 11. 販売前の実行型受入

- Stripe test modeと閉じたlive受入でJPY 400の単発決済を確認済み
- 二重決済の候補、Plus未付与、全額返金、refund pending、refund failed、Webhook再送の処理を確認済み
- 返金成功時だけPlusが終了し、失敗時は誤って終了しないことを確認する
- open dispute中に通常返金を重ねない手順を確認する
- 受領、返金開始、pending・failed、完了の返信文を実際に使えることを確認する
- 返金の実行者、時刻、Stripe状態、Plus終了だけを監査でき、健康情報やSecretを残さないことを確認する

公開後も、異議申立て、返金失敗、配信失敗を日常運用で確認し、解決できない異常時はCheckoutを停止する。
