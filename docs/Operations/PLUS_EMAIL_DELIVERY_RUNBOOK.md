# GlucoScope Plus 確認メール不達・遅延対応手順

## 1. 目的と停止境界

この手順は、Plusの確認コードがすぐ届かない、遅れて届く、bounce・suppressionになる場合に、利用する人を急かさず、安全に再送し、必要なら送信を停止するための運営者用手順である。

- Plusの公開アカウント、販売、Checkoutは、追加の少人数受信箱と本手順の異常系受け入れが終わるまで有効にしない。
- 確認メールが失敗しても、現在血糖やFreeの基本機能を止めない。
- 運営者は6桁コード、メールのパスワード、カード情報、血糖値、CGM接続情報を尋ねない。
- 問い合わせ窓口は `support@glucoscope.app`。平日受付、原則5営業日以内に返信する。緊急・医療相談は受け付けない。

## 2. 利用する人への案内

1. コード画面を閉じず、まず数分待つ。
2. 迷惑メール、プロモーション・更新などの分類、以前のGlucoScopeメールと同じ会話を確認する。
3. 60秒の表示が終わるまで再送しない。安全確認を新しく完了してから「もう一度送る」を1回だけ押す。
4. 再送に成功した後は、いちばん新しいメールの6桁コードだけを10分以内に使う。
5. 送信結果を確認する前に通信が切れた場合、届いたコードは試せる。確認できない、または届かない場合は、60秒待って新しいコードを送る。
6. 数分待っても届かない場合は、連続再送せず問い合わせへ進む。Freeの利用は続けられる。

GlucoScope側は同一メールへの再送を60秒に1回、1時間5回までに制限する。新しいメールの送信が確定した時だけ以前のコードを無効にする。再送が送信前または送信処理中に明確に失敗した場合は、先に正常送信済みのコードを失敗処理だけで無効にしない。

## 3. 運営者の確認順

1. 利用者からは、宛先そのものを公開issueや共有文書へ転記せず、送信したおおよその時刻、画面の一般的なエラー文、初回か再送かだけを確認する。
2. Resend DashboardのEmailsで対象送信を確認する。メール詳細やログの公開リンクを作らず、スクリーンショットを公開資料へ貼らない。
3. 状態を次のように扱う。
   - `sent` / `delivered`: 受信側メールサーバーまで受理された状態。受信箱への表示を保証しないため、分類フォルダと同じ会話を案内し、少し待つ。
   - `delivery_delayed`: 一時的な遅延。連続再送せず待ち、状態の変化を再確認する。
   - `failed`: 送信処理の失敗。Worker、Resend log、rate limitを確認し、原因が分かるまで販売用送信を増やさない。
   - `bounced`: 受信側が拒否。入力間違い、存在しない宛先、受信箱満杯、一時障害など、表示された種別と理由を確認する。
   - `complained`: 迷惑メール報告。対象宛先へ再送せず、原因と送信文面を確認する。
   - `suppressed`: 過去のhard bounceまたは迷惑メール報告等によりResendが送信を止めた状態。原因を解決し、本人が宛先と受信意思を確認するまでSuppression Listから削除しない。
4. `failed`、`bounced`、`complained`、`suppressed`が続く、または通常と異なる増加がある場合は、Plusのアカウント送信flagをOFFのまま維持し、公開販売へ進まない。
5. 原因を直した後は、公式テスト宛先、運営者本人、追加の少人数受信箱の順で、必要最小限の1通だけを再確認する。

Resendの`delivered`は受信側メールサーバーの受理であり、その後の受信箱・迷惑メール・保留・破棄までは示さない。状態の意味は[Managing Emails](https://resend.com/docs/dashboard/emails/introduction)、受信箱に見えない場合は[Delivered but not received](https://resend.com/docs/knowledge-base/what-if-an-email-says-delivered-but-the-recipient-has-not-received-it)、suppressionは[Email Suppressions](https://resend.com/docs/dashboard/emails/email-suppressions)を正とする。

## 4. 受け入れ項目

- 初回送信後、再送ボタンが60秒間無効で残り秒数を表示する。
- 再送には使い回していないTurnstile tokenが必要である。
- 再送成功後、UIが「最新メールのコードだけを使う」と案内し、古いコードを拒否する。
- Resendが明確に失敗した再送では、先に正常送信済みのコードが引き続き使える。
- 429の`Retry-After`をブラウザが上限付きで読み、待機表示へ反映する。
- 迷惑メール、分類フォルダ、同じ会話、数分の遅延を、子どもにも分かる短い言葉で案内する。
- `delivery_delayed`、`bounced`、`complained`、`suppressed`の各状態を、健康情報やSecretを使わずに運営者が見分けられる。
- 送信失敗・受信遅延・問い合わせ中もFreeの血糖表示が続く。

## 5. 記録しないもの

コード、Turnstile token、Resend API key、完全なメールアドレス、非公開転送先、メール本文、血糖値、接続URL・合言葉、カード情報を、Git、公開issue、PROJECT_BIBLEの受け入れ記録、スクリーンショットへ残さない。受け入れ記録には日時、対象環境、状態種別、成功・失敗、停止flag、合成行の削除結果だけを書く。
