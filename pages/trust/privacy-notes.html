現在の公開プレビュー

現在のページはKazuma自身のNightscoutデータを表示する公開サンプルです。公開URLを知る人は表示内容を閲覧できます。

Kazuma自身の公開比較データ

3CGM比較ラボでは、GuardianをKazumaの公開Nightscoutからブラウザで直接読み、LibreとG7は公開デモ専用のCloudflare Workerと期限付きKVを使う構成を準備しています。Kazumaは、自分自身のLibreの血糖値と測定・更新時刻を公開することを明示的に選びました。2026年8月7日には、自分自身のG7の血糖値と測定・更新時刻の公開へも、Libreとは別に明示同意しました。公開URLを知る人は有効化中の値を閲覧できるため、匿名データとは案内しません。この選択はKazuma自身のデモデータだけに適用します。Dexcom G7は、Gluroo表示に加え、1回の定期取得、G7専用KVキー作成、安全な公開Worker応答まで確認しました。確認後は停止Versionへ戻しました。停止中のG7接続先は`dexcomRouteVerified=false`のままフロントへ設定済みですが、GitHub Pagesへの公開反映確認はまだです。現在のページは停止中Workerにより「準備中・合成データ」のままです。

別途有効化した場合、デモ専用Workerは各Gluroo送信先URLとAPI Secretをソース別のCloudflare Secretsだけに置き、直近24時間以内の血糖値、測定時刻、許可した方向情報だけをソース別KVキーへ保存します。KVは最長36時間で期限切れになり、一般利用者向け限定中継とは分けて、アプリケーションログとWorker observabilityを無効にします。公開ページを見てもGlurooへの新しい取得は発生せず、定期実行で更新したKVだけを読みます。

この公開の選択はKazuma自身が明示同意したデモデータだけに適用します。一般利用者の接続情報や血糖データをデモ用WorkerやKVへ保存・公開しません。一時G7 Version `3b796eb5-11be-466f-83ea-7710279f49c1`ではLibreを停止したまま、1回のCronで`public:dexcom-g7:v1`を作成しました。公開応答190件は、許可した項目、型、範囲、時系列順、更新の新しさ、非公開情報を示す項目がないことを、血糖値や測定時刻を表示せず確認しました。直後にdeployment `8de64190-7558-43c6-83c1-1e29a2cf80de`で停止Version `9994a142-a4ca-4885-9077-952ec8e7e8d2`へ100%戻し、両経路は再び`503`です。次の停止中Cron後もG7キーの有効期限は延長されませんでした。KVの生データは直接読み出していません。残ったキーは停止中の経路から配信せず、既存の最長36時間TTLで失効します。Secret値、Gluroo URL、実血糖値、測定時刻は画面出力やGitへ入れていません。停止中のG7接続先は`dexcomRouteVerified=false`のまま設定済みです。GitHub Pagesへの公開反映、G7ライブ表示、3機種同時比較、ページ全体の経路は未確認です。複数回の定期更新と、一般利用者向け限定中継のG7経路も未確認です。

同じく2026年8月7日、別の明示確認後、Libreだけを一時有効にしたVersion `2e72847d-5011-47c5-80e6-8cb931a1b141`を1回の定期更新に限って本番通信へ反映しました。19:25 JSTのCronで公開`/v1/libre`応答が合計523件になったことを確認しました。件数と構造結果だけを使い、上位スキーマ、許可した項目、型、範囲、時系列順、更新の新しさ、確認対象の非公開項目がないこと、CORS境界を確認しました。実際の血糖値、測定時刻、Gluroo URL、Secret、tokenは検査出力やGitへ入れていません。G7は`503`のままでした。確認後すぐ停止Version `9994a142-a4ca-4885-9077-952ec8e7e8d2`へ戻し、両経路が`503`であることを確認しました。次の停止中Cron後もLibreキーの有効期限は延長されませんでした。確認できたのはLibreの1回の定期取得と安全な公開Worker応答までです。

ユーザー版の接続情報

接続先URLと接続用の合言葉は、利用する人が選んだスマートフォンやパソコンのブラウザへ保存します。端末内の保存は特別な暗号化金庫ではないため、共用端末では「この端末に保存する」をオフにするか、利用後に削除してください。

自分のNightscoutへつなぐ場合は、ブラウザから直接読み取り、接続情報と血糖データはGlucoScopeの限定中継機能を通りません。

Glurooのかんたん接続では、GlurooのURL、接続用の合言葉、指定期間、表示に必要な血糖データがCloudflare基盤とGlucoScopeの限定中継機能を一時的に通ります。GlucoScopeのアプリケーションでは、それらを保存、共有キャッシュ、ログ記録、AI送信、他の利用者との共有に使いません。

限定中継は現在停止中です。接続画面では、説明を読んだことへの明示的な同意がない限り、限定中継への通信を始めません。停止中はWorkerがGlurooへ接続する前に要求を止めるため、実データを取得しません。

限定中継機能のDurable Objectsへ保存するのは、UTCの日付と利用回数だけです。Gluroo URL、合言葉、血糖値、測定時刻、レスポンス本文、IPアドレスは保存しません。

Apple、Google、Gluroo、CareLink、Dexcom、Libreなどのログインパスワードを、GlucoScopeへ入力してもらうことはありません。

ユーザー版のAI

現在の共有AIキャッシュは公開デモ向けのため、利用者ごとの分離が完成するまで、ユーザー版からGlucoScopeのAI Workerへ血糖サマリーを送りません。ブラウザ内のいつものお話と、利用者自身がChatGPTへ渡すためのコピー機能は利用できます。

APIキーをブラウザへ置かない

OpenAI APIキー、Turnstileの秘密鍵、限定中継チケットの署名鍵はCloudflare WorkerのSecretとして管理し、GitHub PagesのHTMLやJavaScriptには置きません。

AIへ送る内容

公開デモのAIお手紙では、表示中の期間、TIR、TAR、TBR、平均、CV、GMI、GlucoScore、傾向の要約など、振り返りに必要なサマリーをWorker経由で送ります。個人名や自由記述を必要以上に含めない設計を優先します。ユーザー版は、前の項目のとおり現在送信しません。

利用カウンター

AIの生成回数、トークン数、推定利用額、Turnstile成功・失敗などの運用情報を保存します。血糖値やAIお手紙本文そのものを利用カウンターには保存しません。

AIお手紙のキャッシュ

保存済みAIお手紙は、閲覧したブラウザのlocalStorageと、Cloudflare Workers KVの共有キャッシュを使います。共有KVには生成済みのお手紙本文と必要最小限のメタ情報だけを保存し、送信された血糖サマリーそのものは保存しません。

同じ条件のお手紙は1時間以内なら再利用し、新しいAI生成を行いません。古いお手紙は生成失敗時などのフォールバックとして最大24時間だけ残し、その後は自動削除します。

公開ページのアクセス分析

公開デモなどの公開ページにはCloudflare Web Analyticsを導入し、ページ閲覧や表示性能の全体傾向を確認しています。ただし、ユーザーモード中だけでなく、接続情報がこのブラウザに保存されている間は、AboutやTrustを含むGlucoScope内のページでWeb Analyticsのビーコンを読み込みません。保存状態を安全に確認できない場合も読み込みません。個々の人をGlucoScope内で識別するための独自IDや、独自の行動追跡イベントも追加していません。

ユーザー版で使うChart.jsはGlucoScope内に同梱し、接続情報や血糖データを扱うページで外部CDNのグラフ用JavaScriptを実行しない構成にしています。

血糖値、GlucoScore、AIお手紙本文、Nightscout URL、API情報をアクセス分析のイベント名や追加データとして送る実装は行いません。スマホの各タブ操作も、健康情報を含む個別イベントとして追跡しません。

User connection details

The connection URL and passphrase are saved in the selected browser when the person chooses to save them. Browser storage is not a dedicated encrypted vault, so a shared device should use session-only storage or remove the connection afterward.

An existing Nightscout environment is read directly by the browser. Its connection information and glucose data do not pass through the GlucoScope limited relay.

For the Gluroo easy connection, the Gluroo URL, passphrase, requested range, and glucose entries needed for display pass transiently through Cloudflare infrastructure and the GlucoScope limited relay. The GlucoScope application does not store, cache, log, send to AI, or share those values.

The limited relay is currently paused. The connection screen starts no relay request without explicit consent to the explanation. While paused, the Worker stops before contacting Gluroo and retrieves no live data.

The relay Durable Object stores only a UTC date bucket and request count. It does not store the Gluroo URL, passphrase, glucose values, measurement timestamps, response bodies, or IP addresses.

GlucoScope does not ask for Apple, Google, Gluroo, CareLink, Dexcom, Libre, or other manufacturer login passwords.

User-mode AI

The current shared AI cache is for the public demo. Until per-user isolation is complete, user-mode summaries are not sent to the GlucoScope AI Worker. The local Gluco reflection and copy-to-ChatGPT path remain available.

Secrets stay server-side

OpenAI and Turnstile secret keys and the relay-ticket signing key are stored as Worker secrets, not in browser code.

AI summaries

For public-demo AI letters, only the summary needed for reflection is sent through the Worker. Personal identifiers should be minimized. User-mode summaries are not currently sent, as described above.

Operational counters

Usage counts and estimated developer cost may be stored, but glucose values and letter text are not stored in the usage counter.

AI letter cache

Saved AI letters use browser localStorage and a shared Cloudflare Workers KV cache. KV stores only the generated letter and minimal metadata, not the submitted glucose summary.

The same letter is reused for one hour without a new AI generation. A stale fallback may remain for up to 24 hours and is then deleted automatically.

Public web analytics

Public-demo pages use Cloudflare Web Analytics to review aggregate page visits and performance. The analytics beacon is not loaded in user mode, while a GlucoScope user connection remains in local or session browser storage, or when that storage state cannot be checked. This applies across same-origin About and Trust pages. GlucoScope does not add a custom visitor ID or custom behavioral events.

Chart.js is served from a reviewed local copy on the user-data page instead of running the chart library from a third-party CDN.

Glucose values, GlucoScore, AI letter text, Nightscout URLs, and API information are not intentionally sent as analytics event names or additional analytics data. Mobile tab actions are not tracked as health-data events.
