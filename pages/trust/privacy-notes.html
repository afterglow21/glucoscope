Kazuma自身の公開比較データ

3CGM比較ラボでは、GuardianをKazumaの公開Nightscoutからブラウザで直接読み、LibreとG7は公開デモ専用のCloudflare Workerと期限付きKVを使います。Kazumaは、自分自身のLibreとG7の血糖値・測定更新時刻の公開へ別々に明示同意しました。公開URLから閲覧できる公開・非匿名データであり、この選択はKazuma自身のデモデータだけに適用します。安全対応と別の継続公開判断後、現在は3機種を継続公開中です。`dexcomRouteVerified=true`はG7表示経路の確認記録で、Workerの有効化ではありません。一般利用者向け限定中継は`RELAY_ENABLED=false`のままです。

デモ専用Workerは各Gluroo送信先URLとAPI Secretをソース別のCloudflare Secretsだけに置き、直近24時間以内の血糖値、測定時刻、許可した方向情報だけをソース別KVキーへ保存します。KVは最長36時間で期限切れになり、一般利用者向け限定中継とは分けて、アプリケーションログとWorker observabilityを無効にします。公開ページを見てもGlurooへの新しい取得は発生せず、定期実行で更新したKVだけを読みます。

次の3段落は、一時確認後に停止へ戻した過去のチェックポイントです。現在の継続ライブ状態は、その後の段落に記録しています。

ユーザー版の接続情報

接続先URLと接続用の合言葉は、利用する人が選んだスマートフォンやパソコンのブラウザへ保存します。端末内の保存は特別な暗号化金庫ではないため、共用端末では「この端末に保存する」をオフにするか、利用後に削除してください。

自分のNightscoutへつなぐ場合は、ブラウザから直接読み取り、接続情報と血糖データはGlucoScopeの限定中継機能を通りません。

Glurooのかんたん接続では、GlurooのURL、接続用の合言葉、指定期間、表示に必要な血糖データがCloudflare基盤とGlucoScopeの限定中継機能を一時的に通ります。GlucoScopeのアプリケーションでは、それらを保存、共有キャッシュ、ログ記録、AI送信、他の利用者との共有に使いません。

限定中継は現在、1〜3人の先行体験に限って有効です。接続画面では、説明を読んだことへの明示的な同意がない限り、限定中継への通信を始めません。異常な通信、提供条件の重要な変更、プライバシー上の懸念が見つかった場合は、確認済みの停止Versionへすぐ戻します。

限定中継機能のDurable Objectsへ保存するのは、UTCの日付と利用回数だけです。Gluroo URL、合言葉、血糖値、測定時刻、レスポンス本文、IPアドレスは保存しません。

Apple、Google、Gluroo、CareLink、Dexcom、Libreなどのログインパスワードを、GlucoScopeへ入力してもらうことはありません。

表示名と利用状況

利用状況の記録も現在、1〜3人の先行体験に限って有効です。公開デモを見るだけなら、名前の入力も利用プロフィールの作成もありません。自分のデータを新しくつなぐ人だけが表示名を入力し、利用記録は設定からいつでも停止・再開・削除できます。

表示名と基本的な利用回数を、GlucoScopeをよくするために記録します。血糖値や接続情報は記録しません。

管理者が確認する利用状況は、表示名、過去90日間の利用日、新しく成功したAI分析、通常のグルコの想い出No.1〜50の数です。運営に必要な内部情報として、この端末用のランダムなprofile ID、利用記録の状態、説明版、作成・更新・最終利用日時も保存します。profile tokenはこのブラウザだけに保存し、D1にはtokenのSHA-256 hashだけを保存します。

血糖値、測定時刻、グラフ、TIR/TAR/TBR、CGMの種類、接続情報、AIお手紙本文、Lucky Gluco No.51〜70、Unicorn Gluco、IPアドレス、raw User-Agent、referrer、queryを利用状況のrequest bodyへ入れません。Usage WorkerはIPアドレス、raw User-Agent、referrerを読み取り・アプリログ記録・D1保存しません。Cloudflareは通信・安全対策に必要なネットワーク情報を、Cloudflare自身の方針に基づいて処理する場合があります。利用記録は設定から停止でき、停止しても基本機能は変わりません。

日別の利用記録と、90日利用のない端末プロフィールは、通常のD1データから90日を上限に削除します。機能の公開中は、本人が利用記録を停止し、allowlist形式で書き出し、稼働中のD1から端末プロフィールと関連記録を削除できます。通信に失敗しても、停止または削除を押した端末では先に新しい送信を止め、認証情報を残して書き出し・削除を再試行できるようにします。

利用プロフィール用の安全確認またはUsage Workerだけが一時的に使えない場合も、確認済みの血糖データ接続は止めません。表示名と接続情報をブラウザへ保存して開始し、利用プロフィールは未登録・利用記録停止のままとします。Gluroo限定中継そのものの安全確認と接続先検証は、この例外へ含めません。

Cloudflare D1のTime Travel復旧履歴は常時有効です。稼働中のD1から削除した後も、CloudflareのFreeプランでは最長7日、Paidプランでは最長30日、復旧可能な履歴に残る場合があります。この履歴は通常の画面や管理者集計からは見えません。復旧操作が必要になった場合は収集を停止し、削除済みデータを通常運用へ戻さないことを確認してから再開します。

これはアカウントではなくブラウザごとの端末プロフィールです。同じ人が別端末で使うと別々になり、ブラウザ保存を消すと復旧・統合できません。通常画面には停止・再開・削除の小さな管理導線を置き、書き出しは補助リンクにします。

表示名を保存したかどうかだけで、Cloudflare Web Analyticsを停止・再開しません。利用記録を始められる画面では開始前から読み込まず、端末プロフィールの認証情報がこのブラウザに保存されている間も、その情報を第三者スクリプトと同じページに置かないため読み込みません。

Gluroo限定中継では、接続情報をCloudflareで一時処理することを別に確認します。この確認は利用プロフィールの案内と分けて維持します。血糖・健康データを保存する場合や、本人データを公開共有する場合も、別に明示的な確認を行います。

2026年8月12日の最初の実機確認ではプロフィール作成に成功しましたが、成功後の再コールバックで誤ったエラーが表示されました。既知の試験用プロフィール2件はその後削除し、cascade後の profiles、usage_daily、event_receipts は 0 / 0 / 0 です。続く2回の監督下確認ではどちらも接続確認まで成功しましたが、「GlucoScopeを始める」と短いTurnstile表示の後に必須のデータ接続画面が再表示されました。2回目はUsage Version 5d160aed-7b27-48e6-b0a8-783534f97b6f と限定中継Version a398d59e-54c1-4b8d-a9a4-b779af360a54 を一時有効にし、D1は 0 / 0 / 0 のままで利用プロフィールは作成されていません。直後にUsageを停止Version 7cb71965-74c3-47f9-b589-75cf6d669edb、限定中継を停止Version 635b8ad5-0c0e-49ff-a8c3-5dc3e8704a0a へ戻しました。原因は、ユーザーモードで不要な再読み込みを行い、SafariでsessionStorageの短期リレーチケットを使えない場合に、保存済み接続へ有効なadapterを設定できないことでした。このリリースには、その場でconfigとadapterを有効にするローカルテスト合格済みの修正を含めています。この時点では、監督下実機確認は未完了でした。Gitに保存するWorker設定は false、一般利用者向け限定中継も RELAY_ENABLED=false のままです。

修正版の公開後、3回目のiPhone監督下確認ではGluroo（Libre）の接続に成功し、「GlucoScopeを始める」の後も同じ画面にとどまってライブ血糖を表示できました。一方、D1は profiles / usage_daily / event_receipts = 0 / 0 / 0 のままで、利用プロフィールは作成されていません。このCGM表示の成功によって利用状況を記録したとは扱いません。確認直後、deployment a1962cbf-9f77-48c1-b33a-05bd39323a8c と 17de293b-2d38-4b07-aa5f-604c2cc65d43 で限定中継とUsageを停止Versionへ戻しました。両Workerとも許可Originの事前確認は 204、停止中の送信は 503 です。Gitに保存するWorker設定は false、公開フロントの監督下候補gateは true のままで、一般利用者向け限定中継は停止中です。

その後の監督下iPhone確認では、古い端末認証情報の安全な整理、新しい利用プロフィールの作成、再読み込み後の重複防止と日別記録、停止、再開、allowlist書き出し、削除まで確認できました。 最後の削除でプロフィールと関連記録は稼働中D1からcascade削除され、3テーブルは 0 / 0 / 0 に戻りました。確認後はUsage Workerを停止Versionへ戻し、一般利用者向け限定中継も停止したままです。表示名やprofile IDなどの個別内容は、この公開記録へ残していません。このリリースでは削除完了を画面へ明示し、書き出しを目立たない「詳しい管理」へ整理しました。

一般利用者向け限定中継のDexcom G7経路も、通常Safariで接続確認、期間切替、再読み込み、接続削除まで実機確認しました。 URL、接続用の合言葉、Turnstile token、relay ticket、血糖値はこの記録へ残していません。公開3CGMデモとUsage Workerには触れず、確認後すぐ限定中継を停止へ戻しました。その時点では継続有効化と少人数展開を別の判断として残しました。

別の明示承認後、Usageと限定中継を1〜3人の先行体験として継続有効にしました。 Usage deployment 4fbf0e2c-5f5c-4f4f-98a9-ae57d73b4824 と限定中継deployment 5f8d00d9-9d68-4b2a-99cd-c58c26123684 は、それぞれ受け入れ済みVersionへ通信の100%を向けています。有効化直後のD1は 0 / 0 / 0 のままです。許可Originの事前確認は 204、不正なTurnstileと不許可Originは 403、応答は no-store 境界を維持しています。Gitに保存する両Workerの安全スイッチは false のまま、停止Versionも即時復帰先として保持しています。これは広い一般公開ではありません。

ユーザー版のAI

現在の共有AIキャッシュは公開デモ向けのため、利用者ごとの分離が完成するまで、ユーザー版からGlucoScopeのAI Workerへ血糖サマリーを送りません。ブラウザ内のいつものお話と、利用者自身がChatGPTへ渡すためのコピー機能は利用できます。

APIキーをブラウザへ置かない

OpenAI APIキー、Turnstileの秘密鍵、限定中継チケットの署名鍵はCloudflare WorkerのSecretとして管理し、GitHub PagesのHTMLやJavaScriptには置きません。

AIへ送る内容

公開デモのAIお手紙では、表示中の期間、TIR、TAR、TBR、平均、CV、GMI、GlucoScore、傾向の要約など、振り返りに必要なサマリーをWorker経由で送ります。個人名や自由記述を必要以上に含めない設計を優先します。ユーザー版は、前の項目のとおり現在送信しません。

利用カウンター

AIの生成回数、トークン数、推定利用額、Turnstile成功・失敗などの運用情報を保存します。血糖値やAIお手紙本文そのものを利用カウンターには保存しません。

AIお手紙のキャッシュ

保存済みAIお手紙は、閲覧したブラウザのlocalStorageと、Cloudflare Workers KVの共有キャッシュを使います。共有KVには生成済みのお手紙本文と必要最小限のメタ情報だけを保存し、送信された血糖サマリーそのものは保存しません。

同じ条件のお手紙は1時間以内なら再利用し、新しいAI生成を行いません。古いお手紙は生成失敗時などのフォールバックとして最大24時間だけ残し、その後は自動削除します。

公開ページのアクセス分析

公開デモなどの公開ページには、プライバシーを重視したCloudflare Web Analyticsを導入し、ページ閲覧や表示性能の全体傾向を確認しています。ただし、ユーザーモード中、個人データ接続や利用プロフィールを扱うメイン画面、接続情報または端末プロフィールがこのブラウザに保存されている間、または保存状態を安全に確認できない場合は、AboutやTrustを含むGlucoScope内のページでWeb Analyticsのビーコンを読み込みません。個々の人をGlucoScope内で識別するための独自IDや、独自の行動追跡イベントも追加していません。

ユーザー版で使うChart.jsはGlucoScope内に同梱し、接続情報や血糖データを扱うページで外部CDNのグラフ用JavaScriptを実行しない構成にしています。

血糖値、GlucoScore、AIお手紙本文、Nightscout URL、API情報をアクセス分析のイベント名や追加データとして送る実装は行いません。スマホの各タブ操作も、健康情報を含む個別イベントとして追跡しません。

Kazuma's public comparison data

The 3CGM Comparison Lab reads Guardian directly in the browser from Kazuma's public Nightscout and uses a dedicated Cloudflare Worker with expiring KV for Libre and G7. Kazuma separately consented to publishing his own Libre and G7 glucose values and measurement/update timing. Anyone with the public URL can view these public, non-anonymous values. The choice applies only to Kazuma's demo data. After the frontend safety release and a separate continuing-publication decision, all three sources are now published continuously. `dexcomRouteVerified=true` records G7 display-path verification and does not enable the Worker. The separate general-user Limited Data Relay is currently enabled only for a 1–3 person early-access group.

The next three paragraphs are historical checkpoints that were returned to the stopped state after temporary checks. The later paragraph records the current continuous-live state.

The demo-only Worker keeps each Gluroo source URL and API Secret in source-specific Cloudflare Secrets and stores only glucose values from the latest 24 hours, measurement times, and an allowlisted direction under source-specific KV keys. KV expires within 36 hours. The Worker is separate from the general-user Limited Data Relay, with application logging and Worker observability disabled. Public page views read only scheduled KV snapshots and do not trigger a Gluroo request.

These publication choices apply only to Kazuma's explicitly consented demo data. General-user connection details and glucose data never enter the demo Worker or KV. Temporary G7-only Version `3b796eb5-11be-466f-83ea-7710279f49c1` kept Libre paused while one Cron created `public:dexcom-g7:v1`. The 190-entry public response passed the reviewed field, type, bound, ordering, recency, and private-marker checks without printing glucose values or measurement timestamps. User connection details

The connection URL and passphrase are saved in the selected browser when the person chooses to save them. Browser storage is not a dedicated encrypted vault, so a shared device should use session-only storage or remove the connection afterward.

An existing Nightscout environment is read directly by the browser. Its connection information and glucose data do not pass through the GlucoScope limited relay.

For the Gluroo easy connection, the Gluroo URL, passphrase, requested range, and glucose entries needed for display pass transiently through Cloudflare infrastructure and the GlucoScope limited relay. The GlucoScope application does not store, cache, log, send to AI, or share those values.

The limited relay is currently enabled only for a 1–3 person early-access group. The connection screen starts no relay request without explicit consent to the explanation. Abnormal traffic, a material provider-policy change, or a privacy concern triggers an immediate return to the reviewed stopped Version.

The relay Durable Object stores only a UTC date bucket and request count. It does not store the Gluroo URL, passphrase, glucose values, measurement timestamps, response bodies, or IP addresses.

GlucoScope does not ask for Apple, Google, Gluroo, CareLink, Dexcom, Libre, or other manufacturer login passwords.

Display name and usage

Usage recording passed its supervised lifecycle check and is currently enabled only for a 1–3 person early-access group. Viewing the public demo creates no usage profile and does not require a name. Only a person connecting their own data enters a display name, and usage recording can be stopped, resumed, or deleted from settings.

We record your display name and basic usage counts to improve GlucoScope. We do not record glucose values or connection details.

The administrator-visible usage fields are the display name, visit days from the past 90 days, newly completed AI analyses, and the number of ordinary Gluco memories No. 1–50. Operational fields also include a random profile ID for this browser, usage-recording state, notice version, and created, updated, and last-used times. The profile token stays only in this browser; D1 stores only its SHA-256 hash.

Glucose values, reading times, graphs, TIR/TAR/TBR, CGM type, connection details, AI letter contents, Lucky Gluco No. 51–70, Unicorn Gluco, IP address, raw User-Agent, referrer, and query are not placed in the usage request body. The Usage Worker does not read, application-log, or D1-store IP addresses, raw User-Agent, or referrer. Cloudflare may process network information needed for transport and security under its own policies. Usage recording can be stopped in settings, and stopping it does not change the core features.

Daily usage records and browser profiles inactive for 90 days are removed from the live D1 data within a maximum of 90 days. While the feature is available, the person can stop usage recording, export the allowlisted record, or delete the browser profile and related records from the live D1 database. A failed Stop or Delete request first blocks new sending on that browser and retains the credential so export or deletion can be retried.

If only the usage-profile safety check or Usage Worker is temporarily unavailable, an otherwise verified glucose-data connection is not blocked. The display name and connection are saved in the browser, while the usage profile remains unregistered with recording off. This exception does not apply to the Gluroo relay safety check or destination validation.

Cloudflare D1 Time Travel recovery history is always on. After deletion from the live D1 database, recoverable history may remain for up to 7 days on the Free plan or up to 30 days on a Paid plan. It is not shown in the normal UI or administrator aggregates. If a recovery is ever required, collection will be paused and previously deleted records will be kept out of normal operation before collection resumes.

This is a per-browser profile, not an account. The same person appears separately on another device, and erasing browser storage prevents recovery or merging. The regular UI will keep compact Stop, Resume, and Delete controls, with export as a small secondary link.

Saving the display name alone does not stop or start Cloudflare Web Analytics. The main page does not load it when usage recording can be started, and it also remains off while a browser-profile credential exists, so that credential does not coexist with a third-party script on the page.

The Gluroo Limited Relay keeps a separate confirmation because connection details are processed transiently through Cloudflare. That boundary is not merged into the usage-profile notice. Separate explicit confirmation will also be used for storing health or glucose data or publicly sharing a person's data.

User-mode AI

The current shared AI cache is for the public demo. Until per-user isolation is complete, user-mode summaries are not sent to the GlucoScope AI Worker. The local Gluco reflection and copy-to-ChatGPT path remain available.

Secrets stay server-side

OpenAI and Turnstile secret keys and the relay-ticket signing key are stored as Worker secrets, not in browser code.

AI summaries

For public-demo AI letters, only the summary needed for reflection is sent through the Worker. Personal identifiers should be minimized. User-mode summaries are not currently sent, as described above.

Operational counters

Usage counts and estimated developer cost may be stored, but glucose values and letter text are not stored in the usage counter.

AI letter cache

Saved AI letters use browser localStorage and a shared Cloudflare Workers KV cache. KV stores only the generated letter and minimal metadata, not the submitted glucose summary.

The same letter is reused for one hour without a new AI generation. A stale fallback may remain for up to 24 hours and is then deleted automatically.

Public web analytics

Public-demo pages use privacy-first Cloudflare Web Analytics to review aggregate page visits and performance. The analytics beacon is not loaded in user mode, on the main page while a personal-data connection or usage profile can be handled, while a GlucoScope user connection or usage browser profile remains in browser storage, or when that storage state cannot be checked. This applies across same-origin About and Trust pages. GlucoScope does not add a custom visitor ID or custom behavioral events.

Chart.js is served from a reviewed local copy on the user-data page instead of running the chart library from a third-party CDN.

Glucose values, GlucoScore, AI letter text, Nightscout URLs, and API information are not intentionally sent as analytics event names or additional analytics data. Mobile tab actions are not tracked as health-data events.
