Phase A｜Public Demo Ready

About、免責、安全方針、AIお手紙、スマホ表示を整え、安心して人に見せられる状態をつくります。GitHub PagesでFriends & Family Previewを公開済みです。

Medical & AI Principles、Safety、Privacy Notes、Data Integration Principles、Support Policyを公開向けに整理し、カード名とリンク先が一致する形まで整えました。内容は今後も継続して更新します。

Phase D｜Community Growth

グルコ、血糖みまもりパートナー、開発記録、画面紹介を育て、糖尿病とともに生きる人の声を聞きます。

Phase E｜Sustainability

支援の有無で機能や利用条件を変えない、1回ごとの任意の開発支援を始めました。AI・クラウド・安全性・アクセシビリティ・画面づくりを継続しながら、今後も倫理的で持続可能な方法を検討します。

現在の技術課題

Friends & Family Preview、AI利用カウンター、共有KVキャッシュ、CORS制限、Trust Pack、Web Analytics、初回告知まで進みました。一般利用者向けの最初の実機確認では、途中画面をまとめたガイドだけでは一人で進めにくく、SKIPする画面とアプリの見分け方を一画面ずつ案内する必要があることが分かりました。現在は、Glurooの全画面チェックポイントと、FreeStyle LibreLink・LibreLinkUp・Glurooを見分ける案内へ改訂しています。

既存Nightscoutのブラウザ直接接続は確認済みです。Gluroo Global Connectは、接続先と取得内容を限定したCloudflare Worker、Guardian MonitorからGlurooへの実機送信、Turnstile、約1時間の接続チケット、回数制限まで完成しました。2026年8月6日、Glurooから、EULA等と矛盾しない範囲で今回の使い方は動作し問題ないとの文書回答を受け取り、医療判断、CGMデータ再共有、料金、非提携、問い合わせ責任の境界を公開文面へ反映しました。同日、別の明示的な確認を挟んで限定中継を一時有効化し、Guardian MonitorからGluroo、限定中継、GlucoScopeまでの全経路で、iPhone Safariの現在血糖・グラフ表示と再読み込み後の再表示を確認しました。その後、FreeStyle LibreLink、LibreLinkUp、Gluroo、限定中継、GlucoScopeまでのLibre 2の基本経路でも、現在血糖、グラフ、再読み込み、iOSホーム画面からの復帰を確認しました。確認はSafariのプライベートブラウズで行い、終了時にブラウザ保存情報が残らないのは仕様どおりです。通常タブでSafariを完全終了した後の保存は、再テストを省略したため未確認です。各確認後はすぐ`RELAY_ENABLED=false`へ戻し、停止版、正確なCORS、Secret名、Durable Objectを再確認しました。現在は停止中です。次は期間別・期限切れ・削除・上限の追加確認と、Friends & Familyで継続有効化するかの別の判断です。Dexcom G7はGlurooでの表示と接続情報の準備まで確認しましたが、限定中継と公開デモのライブ経路は未確認で、対応済みとは案内しません。

Guardian 4、FreeStyle Libre 2、Dexcom G7を同じ期間に観察する比較ラボでは、GuardianとLibreをライブ表示し、Dexcomを準備中として正直に示す構成を準備しています。GuardianはKazumaの既存Azure Nightscoutからブラウザで直接読み、Libreは一般利用者向け限定中継とは別のデモ専用Workerが5分ごとに取得して、公開項目だけの期限付きKVへ置き換えます。Kazumaは自分自身のLibreの血糖値と測定・更新時刻を公開することを明示的に選びました。2026年8月7日には、自分自身のG7の血糖値と測定・更新時刻の公開へも、Libreとは別に明示同意しました。この選択はKazuma自身のデモデータだけに適用し、一般利用者のデータは保存・公開しません。Dexcom G7はGlurooまでの表示と接続情報の準備を確認しましたが、ライブ取得、KVスナップショット、フロント接続、公開表示までの全経路は未確認で、G7の値はデモ用KVへまだ保存せず、GlucoScopeでも公開していません。ライブ取得に失敗した場合は合成データと明記して切り替えます。2026年8月6日、別々の明示確認後にデモ専用KV、停止Worker、既存Libre用の2つのCloudflare Secretを準備しました。Cloudflareの公開ルート設定は、通常の`workers.dev`が`enabled=true`、Version別Previewが`previews_enabled=false`です。さらに別の明示確認後、フロント接続先を停止中の`/v1/libre`へ設定し、公開URLで「準備中・合成データ」と3機種のカードが表示されることを確認しました。G7対応を含む停止multi-source Version `9994a142-a4ca-4885-9077-952ec8e7e8d2`は、本番通信の100%へ反映済みです。このVersionでは、`DEMO_FEED_ENABLED=false`、`DEMO_LIBRE_FEED_ENABLED=false`、`DEMO_G7_FEED_ENABLED=false`の3つのゲートと、`GLUROO_DEMO_SOURCE_URL`、`GLUROO_DEMO_API_SECRET`、`GLUROO_DEMO_G7_SOURCE_URL`、`GLUROO_DEMO_G7_API_SECRET`の4つのSecret名を確認しました。`/v1/libre`と`/v1/dexcom-g7`のGETはいずれも停止中の`503`を返し、G7ルートでは許可Originのpreflightが`204`、不許可Originが`403`でした。5分Cron後もKVは空です。Secret値は画面出力やGitへ入れず、一時ログは安全確認後に削除しました。この停止確認ではGlurooから取得せず、KVへ書き込まず、G7のフロント接続先を有効化していません。G7のライブ取得、KVスナップショット、フロント接続、公開表示までの全経路は未確認で、準備中のままです。機器へ順位をつけず、近い時刻の表示差・記録間隔・欠測だけを観察します。

User Foundation

The current phase is revising onboarding from real-device feedback: each optional screen needs an explicit step, app switches need exact app identification, and a participant should be able to proceed without live coaching.

Existing Nightscout browser access is verified. The Gluroo-only relay has Worker reachability, a Guardian Monitor input route, server-side Turnstile, short-lived tickets, request limits, a stopped Worker shell, a Durable Object, the required Secret bindings, and one public target. On 2026-08-06, Gluroo replied in writing that the proposed use should work and was acceptable only while it remains consistent with their EULA, terms, and other documents. The public boundary records the medical-decision restriction, no legal assurance about CGM re-sharing, no marketing as a free subscription-Nightscout alternative, possible future GGC subscription, non-affiliation, and GlucoScope-owned support responsibility. A separately approved temporary enablement then completed the first Guardian path from Guardian Monitor through Gluroo, the relay, and GlucoScope in iPhone Safari; current glucose, graph display, and display after reload passed. Later the same day, the basic FreeStyle Libre 2 path from FreeStyle LibreLink through LibreLinkUp, Gluroo, the relay, and GlucoScope passed current glucose, graph display, reload, and return from the iOS Home Screen. That check used Safari Private Browsing, whose browser-stored configuration was removed on close as expected; normal-tab persistence after fully quitting Safari was not retested. The relay was returned immediately to `RELAY_ENABLED=false` after each check, and the stopped Version, exact CORS, Secret names, and Durable Object binding were rechecked. Extended period, expiry, deletion, and limit checks and a separate continuing-enablement decision remain before a low-volume Friends & Family rollout. Dexcom G7 readings and connection-detail preparation are confirmed in Gluroo, but the limited-relay and live public-demo paths remain unverified and are not described as supported.

A separate 3CGM Comparison Lab is being prepared to show Guardian and Libre live while Dexcom G7 is honestly marked as pending. Guardian is read directly in the browser from Kazuma's existing Azure Nightscout. Libre uses a demo-only Worker, separate from the general-user Limited Data Relay, that refreshes an expiring sanitized KV snapshot every five minutes. Kazuma explicitly chose to publish his own Libre glucose values and measurement/update timing. On 2026-08-07, he separately and explicitly chose to publish his own G7 glucose values and measurement/update timing. These choices apply only to Kazuma's consented demo data and never to general-user data. G7 readings and connection-detail preparation are confirmed in Gluroo, but live retrieval, KV snapshot creation, frontend connection, and the public end-to-end path remain unverified; no G7 value has been stored in demo KV or published by GlucoScope. A failed or unconfigured live load falls back to a clearly labelled synthetic dataset. On 2026-08-06, separate explicit approvals created the dedicated KV namespace and stopped Worker and registered the two existing Libre Cloudflare Secrets. Cloudflare's route-level setting reports the normal `workers.dev` route as `enabled=true` and versioned Preview routing as `previews_enabled=false`. After another explicit approval, the frontend configuration was set to the stopped `/v1/libre` route, and the public URL was verified with the clearly labelled `準備中 · 合成データ` fallback and all three device cards. Stopped multi-source Version `9994a142-a4ca-4885-9077-952ec8e7e8d2`, including the G7 route, now receives 100% of production traffic. That Version was verified with all three gates false—`DEMO_FEED_ENABLED=false`, `DEMO_LIBRE_FEED_ENABLED=false`, and `DEMO_G7_FEED_ENABLED=false`—and exactly four Secret names: `GLUROO_DEMO_SOURCE_URL`, `GLUROO_DEMO_API_SECRET`, `GLUROO_DEMO_G7_SOURCE_URL`, and `GLUROO_DEMO_G7_API_SECRET`. GET requests to both `/v1/libre` and `/v1/dexcom-g7` returned paused `503` responses; the G7 route returned `204` for an allowed-Origin preflight and `403` for a disallowed Origin. KV remained empty after the five-minute Cron. Secret values did not enter captured output or Git, and temporary logs were removed after verification. These stopped checks made no Gluroo retrieval, no KV write, and no G7 frontend activation. Live G7 retrieval, KV snapshot creation, frontend connection, and the public end-to-end path remain unverified and pending. The lab observes display differences, cadence, and missing points without ranking devices.
